# PiManager 发布说明

跨平台 GUI，用于配置、切换、测试和启动官方 Pi Coding Agent（`@earendil-works/pi-coding-agent`）。

当前版本：**v1.8.9**

源码仓库：https://github.com/suimi8/PiManager  
预编译包与 VSIX：https://github.com/suimi8/PiManager/releases/tag/v1.8.9

## v1.8.9 更新

> 桌面端围绕「尽快配好、立刻知道能不能用」收敛界面与中断体验。Cursor 扩展仍为配套 **0.7.5**（本版未改扩展）。

### 界面

- **概览摘要**：默认模型、连接状态、已配置 Provider、最近测试；未设默认 / 未测 / 失败用页内横幅给出下一步
- **模型列表**：筛选与操作拆分、结构化属性、失败原因与下一步、窄窗自动隐藏次要列
- **状态语义统一**：成功 / 警告 / 失败 / 进行中；短成功用 Toast，导入配置与测试摘要等长结果走页头下方可关闭面板
- **导航**：侧栏分组（概览 / 配置 / 运行 / 系统）、选中色条、折叠 Tooltip、`Ctrl+1..9` 等快捷键
- **各页补齐**：空状态、设置未保存确认、向导分步验证、Chat 上下文与停止生成、插件未信任提示、工具页用途说明
- **小屏与浅色**：窗口下限 800×600；窄窗自动收起侧栏（不覆盖手动折叠偏好）；浅色主题；对话框按可用屏幕裁切

### 可靠性

- 快速提问点停止会中断 RPC，并结束对应 pi 进程树；健康检查 / 刷新模型 / 自检 / 更新检查可取消
- 密钥库热路径缓存与 `pi-manager.json` 原子写加固

## v1.8.7 更新

> 本轮包含 1.8.6 之后已合入但未发版的安全与健壮性修复，以及 Grokified 中转适配。
> 以下破坏性变更**改变了既有行为**，升级前请阅读。Cursor 扩展请同步安装本版
> 配套 VSIX（**0.7.4**）。

### 功能

- **新增 Grokified（Grok 中转）一键模板**：Base URL `https://api.grokified.com/v1`，
  预填 grok-4.6 / 4.5 / 4.3 / grok-build-0.1。`GET /v1/models` 会打到 xAI，上游
  过载时返回 503，选用本模板后只需粘贴 `gk_live_` 开头的 Key 即可保存，不必等拉取成功
- **上游 5xx / `upstream_overloaded` 自动重试**：模型列表拉取、HTTP 连通测试、快速提问
  在同一模型上短暂重试（最多 3 次），避免把瞬时过载误报成 Key 填错或无法对话；
  401/429 仍走原有 Key 轮换，不会误重试
- **手填不完整模型自动补全**：只写 `{"id":"grok-4.5","name":"grok-4.5"}` 时，保存与
  加载会补上与「添加模型」相同的 `reasoning` / `contextWindow` / `maxTokens` /
  `thinkingLevelMap`，修复「能保存但 Pi 无法对话」
- **密钥池支持明文查看与复制**（默认仍掩码）；OpenAI 兼容 Provider 自动注入
  WAF 友好的 User-Agent；高 DPI 下导航 SVG 图标不再被裁剪
- **下架插件清理连带回收孤儿安装锁**；外部输入读取容忍 UTF-8 BOM

### 破坏性变更

- **旧版 `local:` 格式的 `secrets.vault` 不再可读**：该格式用硬编码 XOR 密钥，
  任何本地写入者都能构造合法密文并注入凭据，且注入内容会被自动重写成 DPAPI 格式
  「洗白」。已**永久移除**解密支持，无迁移开关。若你的 vault 仍是该格式，
  升级后需在「Provider 管理 → API Keys」重新填入密钥
- **明文 JSON 格式的 `secrets.vault` 默认拒绝读取**：需临时设
  `PI_MANAGER_ALLOW_LEGACY_VAULT=1` 启动一次完成迁移（迁移后立刻重写为认证加密），
  之后请取消该变量
- **旧式「裸环境变量名」形式的 apiKey 仅在该变量当前确实存在时才自动迁移**：
  此前 `^[A-Z][A-Z0-9_]{2,}$` 的启发式会把 `AKIAIOSFODNN7EXAMPLE` 这类**真实密钥**
  当成变量名，直接明文写进 `models.json` 且在界面上不打码。现在只承认显式的
  `$NAME` / `${NAME}`；无法确认是变量名的一律当真实密钥存入安全存储
- **`AGENTS.md` 默认不再随配置包导入**：覆盖它等于让下一次运行的 Pi 遵循配置包
  作者的指令（Pi 有 shell 权限），是一条间接提示注入通路。导入结果会明确列出被跳过项
- **含可执行语义键的 `settings.json` 配置包会被拒绝导入**（`hook` / `mcpServer` /
  `command` / `shell` / `exec` / `helper` / `interpreter` / `env` / `permissions`）
- **`--print-provider-env` 现在要求出示 broker token**：此前它零认证即可吐出明文
  API Key，而只写白名单字段的 `--config-mutate` 反而要 token，授权模型是倒置的。
  **旧版 Cursor 扩展（VSIX）会因此取不到密钥，请同步升级扩展**
- **Provider / 模型名施加字符白名单**（字母、数字与 `. _ - : / @`）：含 `"` `&` `|`
  等字符的名字会拒绝启动 Pi。这些字符此前可经 Windows `cmd.exe` shim 注入任意命令
- **便携单文件版不再读取 exe 同目录的 `assets/`**：此前该目录优先级高于内嵌资源，
  在 exe 旁放一个 `assets/builtin/manifest.json` 即可让应用把攻击者的内置扩展
  （拥有完整系统权限）落盘到 `~/.pi/agent/extensions/`

### 其他

- Windows 上 `.broker-token` / `secrets.vault` / `.vault_master_key` /
  `secrets.index.json` / `pi-manager-helper.json` 现在会真正收紧 DACL 到仅当前用户
  （此前的加固代码因三处 ctypes 声明错误 + `except Exception: pass`，在所有 Windows
  机器上都是空操作）
- Windows 上 Cursor 扩展的 helper 自动发现恢复可用（此前因把 POSIX 的 mode 位检查
  用在 Windows 上而 100% 失效，只能落到未校验的回退路径）；扩展版本 **0.7.4**
- 提问超时若发生在 RPC `prompt` 应答返回前，不再以 `unhandledRejection` 打崩扩展宿主
- 迁移明文密钥后会自动擦除仍含明文的 `models.json.bak.*` 与残留 `.tmp`
- macOS `.app` 打包改用保留符号链接的方式，修复解压后 ad-hoc 签名失效导致的
  「已损坏，无法打开」

## v1.8.6 更新

- **移除内置插件 `geonode-ip-rotator`（安全 / 合规）**：该插件在 API 返回 HTTP 402/429（额度耗尽 / 限流）时自动轮换住宅代理出口 IP 并重试请求，实质是绕过 LLM 提供商的额度与计费强制，违反主流提供商的服务条款；又因 manifest 未声明 `enabled_by_default`（代码默认 `true`），它会在用户保存 Provider 配置时静默落盘到 `~/.pi/agent/skills/`，未经用户同意即对全部用户生效。现已从内置清单与随包资产中彻底移除
- **新增已下架内置插件自动清理**：`builtin_plugins._RETIRED_BUILTINS` 登记下架目录，`install_all_builtins()` 在落盘前主动删除用户机器上的残留（仅从 manifest 删条目不会删磁盘上的文件，pi 会继续加载它）；只删白名单内的固定目录，复用与落盘同一套越界校验，单项删除失败非致命且不阻断安装
- **v1.8.5 已撤回**：该版本的 GitHub Release 与预编译包已下架，请升级到 v1.8.6；升级后首次保存 Provider 配置即自动清理残留
- **Windows 发布产物精简**：发布包只保留便携单文件版（onefile），移除目录版；打包脚本 `scripts/package_release.py` 与其测试契约同步更新（原属 v1.8.5，随其撤回并入本版）

- 白天模式下使用教程配色可读；全局标签默认透明底

## 主要功能

1. 自定义 Provider 与模型配置、拉取和批量测试
2. Provider 多 API Key、安全存储和 Pi 子进程运行时注入
3. OS keyring 优先，DPAPI/AES-GCM 当前用户文件库回退

5. 全局代理、健康监控、测试历史和并发测试

8. Cursor 扩展通过 PiManager helper 安全获取运行时环境
9. Windows、macOS、Linux 终端启动支持

## Provider 密钥

真实 API Key 不写入 `models.json`。配置文件仅保存官方 Pi 支持的环境变量引用：

```text
${PI_MANAGER_PROVIDER_<SLUG>_<HASH>_API_KEY}
```

PiManager 启动官方 Pi 时从安全存储读取真实 Key，并只注入该子进程环境。

同一 Provider 的多把 Key 共用该环境变量引用。明确的 Key 错误会将当前 Key 暂时标为失效并切换下一把；可在 **Provider 管理 → API Keys** 恢复。网络错误和服务端 5xx 不会停用 Key。
