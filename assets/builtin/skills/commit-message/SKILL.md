# 规范提交信息

## 项目提交规范（必须遵守）

1. **前缀**（标题首词，英文冒号）：
   - `@fix:` 修复 bug / 问题
   - `@feat:` 新功能 / 能力
   - `@refactor:` 重构（行为不变）
   - `@docs:` 文档改动
   - `@test:` 仅测试改动
   - `@chore:` 构建 / 工具 / 依赖等杂项
2. **标题**：前缀 + 空格 + 简短中文摘要（≤ 50 字），概括核心改动。
3. **正文**：空一行后，用中文要点列出主要改动（每行 `- ` 开头），按重要性排序。
4. **关联上下文**：如涉及多个文件，要点里写清「文件范围」或「子系统」。
5. **不做的事**：不要把密钥、真实域名、服务器地址、用户历史数据写进提交信息；涉敏内容一律用占位符（如 `example.com`、`<REDACTED>`）。

## 执行步骤

1. **查看待提交内容**：

   ```bash
   git status --short
   git diff --stat
   ```

2. **查看具体改动**（新增/改动较大时）：

   ```bash
   git diff            # 已暂存 + 未暂存（如无暂存则看全部）
   # 或按文件:
   git diff -- <file>
   ```

3. **判断变更类型**，选择前缀：修复 bug → `@fix:`；新增功能 → `@feat:`；重构/抽取 → `@refactor:`；仅文档 → `@docs:`；仅测试 → `@test:`；构建/打包/工具 → `@chore:`。多类型并存时，以最主要的一项作前缀，正文要点里分别说明。

4. **生成提交信息**，格式示例：

   ```text
   @fix: 修复导航栏插件图标缺失与底部按钮区重叠

   - 新增 assets/icons/plugins.svg（插件菜单恢复图标，与其他项对齐一致）
   - navButton 文字左对齐；footer 高度改用常量计算并在主题应用后重算，
     修复「启动 Pi」按钮与工具按钮行重叠、被裁剪问题
   - 导航菜单移入滚动区，小窗口时菜单滚动、底部按钮区固定不溢出
   - APP_VERSION 1.8.1 → 1.8.2
   ```

5. **暂存并提交**（执行前向用户展示提交信息，确认后再执行）：

   ```bash
   git add -A
   git commit -m "标题" -m "正文（要点）"
   ```

   > 多要点时可用 heredoc：
   ```bash
   git commit -F - <<'EOF'
   @fix: 标题

   - 要点1
   - 要点2
   EOF
   ```

## 注意事项

- 提交前先 `git diff` 确认没有误加敏感文件（如 `secrets.vault`、`release-assets/`、含密钥的配置）。
- 若工作区有未跟踪的敏感文件（如本地密钥库），**不要** `git add -A` 一把梭，应明确排除或先加入 `.gitignore`。
- 提交信息保持简洁：标题一句话，正文 2-8 条要点；避免长篇大论。
- 用户说「直接提交」时，按上述流程走完并执行；用户说「只生成」时，仅输出提交信息不执行命令。
